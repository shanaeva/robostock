# Контракт API

Общий префикс `/api`. Тела запросов — JSON. Frontend отправляет cookies через `credentials: 'include'`. Все POST требуют предварительного получения CSRF-cookie и заголовка `X-CSRF-Token`. Для браузера `Origin` должен совпадать с `FRONTEND_ORIGIN`.

| Метод и путь                     | Тело                                                                                | Результат                                                                             |
| -------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| GET `/health`                    | —                                                                                   | Доступность API                                                                       |
| GET `/auth/csrf`                 | —                                                                                   | `{ csrfToken }` и CSRF-cookie                                                         |
| GET `/auth/settings`             | —                                                                                   | `{ emailEnabled: boolean }`; публичный режим авторизации                              |
| POST `/auth/register`            | `{ name, email }` при включённой почте; `{ name, email, password }` при выключенной | 202, общее сообщение; код при включённой почте, регистрация с паролем при выключенной |
| POST `/auth/verify-email`        | `{ email, code, password }`                                                         | 200; подтверждение адреса и установка пароля                                          |
| POST `/auth/resend-verification` | `{ email }`                                                                         | 202, общее сообщение                                                                  |
| POST `/auth/login`               | `{ email, password, rememberMe }`                                                   | 200, `{ user }` и HttpOnly cookies                                                    |
| GET `/auth/me`                   | —                                                                                   | 200, `{ user }`; без сессии — 401                                                     |
| POST `/auth/refresh`             | —                                                                                   | 200, `{ user }` и новая пара cookies                                                  |
| POST `/auth/logout`              | —                                                                                   | 200, отзыв текущей сессии и удаление cookies                                          |
| POST `/auth/logout-all`          | —                                                                                   | 200, отзыв всех сессий; требуется активная сессия                                     |
| POST `/auth/forgot-password`     | `{ email }`                                                                         | 202, общее сообщение; отправка кода                                                   |
| POST `/auth/reset-password`      | `{ email, code, newPassword }`                                                      | 200, смена пароля и отзыв всех сессий                                                 |

Публичная модель пользователя: `id`, `name`, `email`, `emailVerified`. Остальные поля не выдаются.

`AUTH_EMAIL_ENABLED` принимает только `true` или `false`, по умолчанию `true`. При `false` регистрация требует пароль от 8 до 128 символов, не создаёт почтовый код и позволяет вход без подтверждения. В `/auth/login`, `/auth/me` и `/auth/refresh` поле `emailVerified` отражает реальное подтверждение адреса; у нового аккаунта без почты оно `false`. При `true` пароль на первом шаге регистрации запрещён, а неподтверждённый пользователь войти не может.

При выключенной почте корректные запросы к `/auth/verify-email`, `/auth/resend-verification`, `/auth/forgot-password`, `/auth/reset-password` возвращают 503 с `code: EMAIL_DISABLED`, независимо от существования пользователя. CSRF, Origin, валидация и ограничения запросов продолжают действовать. Код, пароль и токены не возвращаются в ответах регистрации. Повторная регистрация существующего email не меняет аккаунт; ответ одинаков для нового и существующего адреса в каждом режиме.

Ошибки содержат читаемое `message` и при необходимости машинный `code`. Некорректные/лишние поля — 400; отсутствие сессии — 401; неверная CSRF-проверка — 403; ограничение запросов — 429. UI не показывает сырые ошибки базы или stack trace.

Вход с неверным паролем, отсутствующей учётной записью или неподтверждённой почтой при включённом почтовом режиме возвращает одинаковую ошибку `INVALID_CREDENTIALS`. Отдельного ответа `EMAIL_NOT_VERIFIED` нет. После успешного входа интерфейс открывает `/profile`; профиль читает пользователя из кеша запроса `me`, отдельной клиентской копии пользователя нет.

При включённой почте ответ 202 при регистрации или запросе кода — общее подтверждение приёма запроса, а не гарантия доставки письма. В локальном окружении письма доступны в Mailpit по `http://localhost:8026` (или `MAILPIT_URL`), внешняя доставка не настроена.

Email приводится к нижнему регистру и очищается от пробелов по краям. Пароль не обрезается. При подтверждении почты (`password`) и сбросе пароля (`newPassword`) длина должна быть от 8 до 128 символов; иначе возвращается 400. Коды — ровно шесть цифр.
