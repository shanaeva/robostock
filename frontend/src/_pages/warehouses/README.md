# ROBO-19: Мои склады

Запуск из `frontend`: `npm run dev` (или `pnpm dev` при рабочем launcher pnpm),
затем открыть `/warehouses`. Запуск npm-скрипта не меняет зависимости или lock-файл.

Это демонстрационный режим: API складов и авторизация ещё не подключены.
Каждое открытие страницы создаёт отдельный модуль данных и QueryClient.
Изменения хранятся в памяти и сбрасываются при полной перезагрузке.

## Ручная проверка

- `/warehouses` — четыре склада, обе роли, поиск совместно с фильтром.
- `/warehouses?demo=empty` — пустой список; создание первого склада работает.
- `/warehouses?demo=error` — первая загрузка завершается ошибкой; «Повторить» загружает список.
- `/warehouses?demo=mutation-error` — операции завершаются ошибкой; формы сохраняют значения, записи не удаляются.
- `/warehouses?demo=forbidden` — действия над существующими складами возвращают 403; создание собственного склада остаётся доступным.

Переходить между сценариями следует с полной перезагрузкой страницы.
Переключателей сценариев в обычном интерфейсе нет.

Проверить:

1. Отправить пустое название и название из пробелов: ошибка рядом с полем.
2. Создать склад с пробелами по краям: название обрезается, роль — «Владелец».
3. Переименовать склад, отменить удаление, затем подтвердить удаление.
4. У наблюдателя нет действий изменения, удаления и приглашения; создание собственного склада доступно.
5. Приглашение: проверить email и увидеть подтверждение демо-сценария без обещания отправки письма.
6. Проверить Tab/Shift+Tab, Escape, начальный и возвращаемый фокус; при удалении начальный фокус — «Отмена».
7. Проверить ширины 375 и 1280 px: карточки / таблица, отсутствие горизонтального переполнения.

## Допущения и интеграция

- `Warehouse` — модель отображения с `id`, `name`, `currentUserRole`, не утверждённый DTO.
- Названия обязательны и обрезаются по краям. Уникальность и максимальная длина не вводились.
- Приглашение по email с ролью Observer — демонстрационное допущение. Почта, принятие приглашения и права доступа не реализованы.
- Скрытие действий в UI не является защитой. Моки дополнительно проверяют роль и умеют возвращать 403; реальный API должен проверять права независимо.
- Маршрут экрана склада не согласован, поэтому «Открыть» недоступно.
- QueryClientProvider находится только в границах страницы. Корневой layout и конфигурация не меняются.
- Button, Input и Dialog адаптированы из shadcn/ui (MIT) без CLI init, глобальных CSS-токенов и анимационных зависимостей.

Vitest/RTL во frontend пока не настроены. Предлагаемый отдельный шаг: добавить
Vitest, jsdom, React Testing Library, jest-dom и user-event, затем автоматизировать
перечисленные выше сценарии и тесты моков. Другой тестовый стек не добавлялся.
